## Package installation

The official scaffold was generated separately with `npx create-expo-app --template blank-typescript --no-install --no-agents-md --yes`, then its configuration/assets were merged without overwriting existing documents. `npm install` installed that template's generated base dependency set.

Requested libraries and Router companions were added with:

```sh
npx expo install expo-router react-native-safe-area-context react-native-screens expo-linking expo-constants expo-sqlite expo-secure-store expo-file-system expo-camera expo-keep-awake expo-haptics expo-notifications expo-local-authentication expo-sharing zustand zod fast-xml-parser @google/genai drizzle-orm --npm
npx expo install react-native-reanimated react-native-worklets --npm
npx expo install react-dom --npm
npx expo install --dev drizzle-kit --npm
```

The first animation dependency install encountered a React DOM peer conflict. Running the Expo installer for `react-dom` resolved it while retaining Expo-selected React, Reanimated and Worklets versions. No `--force`, `--legacy-peer-deps`, hand-written version override or forced audit fix was used. These Router companion packages are not the deferred media/measurement stack.

All requested runtime dependencies exist locally; `drizzle-kit` is in `devDependencies` only. The generated `package-lock.json` records the exact graph for `npm ci`. Expo selects compatible versions for packages it knows; other libraries use npm resolution through the same command. See [Expo Router installation](https://docs.expo.dev/router/installation/) for the companion-package and entry-point setup.

`expo-sqlite`, `expo-secure-store` and `expo-sharing` config plugins were added by the installer. Camera permission behavior, reminders, biometric access, Drizzle schema/migrations, Gemini requests and export behavior are not implemented merely by installing the modules.

## Dependency advisory findings

At installation, `npm audit` reported **18 moderate affected-package findings, zero high and zero critical**. These are dependency-tree findings, not 18 independent confirmed app exploits. Reported chains include Expo/Xcode tooling through `uuid`, Router through `query-string` / `decode-uri-component`, and Drizzle Kit's older esbuild tooling.

The audit's main automatic resolutions propose major downgrades of Expo, Router, Sharing or Drizzle Kit, which would undermine the selected SDK setup. They were not applied. No clean security-audit result is claimed. Recheck supported upstream fixes before enabling affected URL processing or exposing development tooling; keep this as a dependency follow-up during implementation rather than introducing manual package-version overrides now.

npm also reported unapproved lifecycle scripts. The inspected Google SDK preinstall is a no-op and the inspected protobufjs postinstall only checks version conventions; their imports do not require granting extra script execution. Drizzle Kit's version command runs with the installed esbuild packages. No blanket lifecycle-script approval was added.
